@@ projects-teams-and-access | How to set up a project and its team | Create a project, add owners, members and viewers, and control who can see it.
1. Create a **project**.
2. Add its team. Each person is an **owner**, a **member** or a **viewer**.
3. Make sure the project has an owner. The only owner cannot be removed.

Users see only the projects they belong to. Administrators see all projects.

## Permissions

Permissions are set per area: projects, boards, labels, sprints and issues. They are enforced on both the server and the screen, so for example drag-and-drop is disabled for someone without edit rights.

## Issues

Create **issues** in the **backlog**. Use **labels** to categorise them and **comments** to discuss them. Open an issue to see its details in the issue drawer. When you **assign** an issue, the assignee is notified.

## Sprints

**Start** a sprint with the issues you will do, and **complete** it when it ends.

## The board

The **kanban board** shows issues as cards in **columns**. Drag a card to move it, and manage the columns to match your process.

## AI assistant

The AI assistant can list and create issues for you, and asks you to confirm before it creates anything. See [AI assistant](/docs/ai-assistant/ask-it-confirm-it).
